# 상주 장례 마감 허브 (samga-closeout-hub)

삼가 서비스기획팀장 2차 면접용 **신규사업 가설 데모**. 기존 자산(모바일 부고·장례식장 ERP·답례·장지·상담)을 상주의 장례 마무리 행동과 사업 결과로 연결하는 가설을 화면·작동 흐름으로 증명한다.

> **가설 · 가상 데이터 · 검증 전 · 실제 서비스 아님.** 기존 `그 다음(geudaeum-*)`·`carebridge` 프로젝트와 별개의 신규 독립 프로젝트다.

## 구성 (정적 웹 · 빌드 불필요)

| 경로 | 화면 | 내용 |
|---|---|---|
| `/` (`index.html`) | 요약 허브 | 사업 가설·기존 자산·솔루션 흐름·핵심지표·Go/Pivot/Stop을 한눈에 |
| `/deck.html` | 발표자료(피치덱) | 10장 슬라이드(키보드 ←→·목차·PDF 인쇄) |
| `/prototype.html` | 모바일 프로토타입 | 11상태 클릭 시연 + 사업 대시보드(데스크톱은 중앙 프레임+설명 패널) |

## 실행

정적 HTML/CSS/vanilla JS. 빌드 도구 없음.

```bash
# 로컬 미리보기
python3 -m http.server 8080   # http://localhost:8080
```

Vercel은 루트를 정적으로 서빙한다(`index.html`).

## 프로토타입 흐름

`제안 → 목적별 동의 → 마무리 홈 → 답례 메시지 → 발송 확인 → 답례품(선택/건너뛰기) → 후속 도움(선택) → 완료 → 사업 대시보드`

- 상태: `offer / consent / home / message_edit / message_review / gift_choice / aftercare_choice / aftercare_detail / complete / dashboard / optout`
- 분기: 모두 거절 · 답례 메시지만 · 답례품 포함 · 사후절차 선택
- 뒤로 가기·처음부터 다시 시작 지원. 이벤트는 로컬 상태에 기록되어 대시보드 퍼널에 반영.

## 가상 데이터 원칙

- 실제 고인·상주·연락처·계좌·결제·문자발송·본인인증 **없음**. 브라우저 상태만 사용.
- 인물·장소·상품·숫자는 모두 가상. 지표는 `기준선 측정 전` 또는 `가상 예시`.
- 법률·세무는 정보·공식 출처·연결까지만. 개인별 판단·자격 판정·대리 수행 없음.

## 디자인 원칙

차분·존엄·비상업. 오프화이트/차콜/네이비 절제 팔레트. 세일 배지·카운트다운·강조 레드·성장 그래프 과장 금지. WCAG AA·44px 터치·키보드 탐색·모션 감소 존중.
